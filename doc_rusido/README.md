# **РУСИДО Tools — концепция програмного комплекса**

**РУСИДО Tools** — набор Python-инструментов для работо с искуственим язике Русидо. Он должен решать два основние задачи:

1. **Руский → Русидо:** автоматически переводить обичний руский текст в соответствии с граматикой Русидо.
2. **Валидатор Русидо:** проверять, соответствует ли текст алфавиту, лексике, морфологии и синтаксису язико, находити ошибки и предлагать исправления.

Дополнительно комплекс должен включать обратний анализатор Русидо, морфологический генератор, словар, API для стороних програм и консольний интерфейс.

Я би проектировал его не как набор отдельних скриптов, а как небольшой лингвистический движок с общей граматикой.

## **1. Архитектурная концепция**

**Общая схема**

**Входной текст**

Руский или Русидо

**Переводчик**

Руский → Русидо

**Валидатор**

Проверка Русидо

**Общее лингвистическое ядро**

Токенизатор · Лексикон · Морфология · Граматика · Парсер

**spaCy**

Синтаксис и контекст

**pymorphy3**

Морфология руский

**NLTK**

Корпуса и статистика

**Результат**

Текст · AST · Диагностика · JSON · Отчет

Ключевое архитектурное решение: **переводчик и валидатор должни использовать одну и тот же формальную граматику Русидо**.

Например, если в граматике существительное образуется по схеме:

```
ОСНОВА + Числ + ПАДЕЖ
```

тот генератор обязан создавать форми по етот схеме, а валидатор — распознавать их по тот же схеме. Иначе с време переводчик начнет создавать форми, которие собствений валидатор будет будти считать ошибочними.

### **2.1. pymorphy3**

Основной инструмент для анализа исходного руский текста.

Он позволяет получати несколько вариантов разбора одного слово, его нормальную форму и граматические признаки. Например, слов `стали` может будти существительним или глаголом, поетому нельзя простий брати первий вариант разбора без учета контекста.&#x20;

Морфологический анализатор pymorphy3+1



Основние задачи:

- определение начальной форми;
- определение части речи;
- определение рода, число и падежа;
- определение времо, вида, лицо и залога глагола;
- получение вариантов морфологического разбора.

### **2.2. spaCy**

Используется для контекстного анализа.

Рекомендуемий исходний компонент — рускоязичная модель `ru_core_news_sm`. Она предоставляет морфологический анализ, синтаксический парсер и лематизацию. В ее конфигурации также используется pymorphy3 для лематизатора.&#x20;

Задачи:

- разделение текста на предложениу;
- определение границ словио;
- определение синтаксических связей;
- поиск подлежащего, сказуемого и дополнения;

### **2.3. NLTK**

NLTK не должен будти основой граматического анализатора. Для етот у ми будет будти собственая граматика.

Его хороший использовать для вспомогательних задач:

- обработка и подготовка корпусов;
- построение частотних словарио;
- анализ биграм и триграм;
- расчет BLEU и других метрик сравнения переводов;
- иследование статистических закономерностей в текстах Русидо.

Для руский токенизации и морфологии предпочтительнее использовать spaCy и pymorphy3, а не полагаться на стандартний английский режим `word_tokenize` NLTK.&#x20;

## **3. Два основних компонента**

### **3.1. Транслятор&#x20;**`RusidoTranslator`

Задача — переводить руский текст на Русидо, сохраняя смисл исходного предложениу и применяя правилиу искуственого язико.

Пример:

**Вход:**

```
Мой брат жит в болший городе.
У он бует два собаки.
Вчера я прочел интересий книгу.
Завтра ми будеми будти работати вместе.
```

**Виход:**

```
мой брат жит в болший городе.
У нему естет два собаки.
Вчера я прочел интересий книгу.
Завтра ми будеми работати вместе.
```

Етот пример целевого поведения, а не окончательная таблица преобразований: точние основи некоторих словио и морфологические форми нужний закрепить в словаре Русидо.

#### **Етапи перевода**

1. **Нормализация**

   Очистка пробелов, Unicode-нормализация, сохранение пунктуации и исходного регистра.
2. **Токенизация**

   Разбиение текста на предложениу, слово и знаки препинания.
3. **Морфологический анализ**

   Получение лем и граматических признаков каждого слово через pymorphy3 и spaCy.
4. **Контекстний анализ**

   Построение синтаксических связей: субьект, обьект, сказуемое, определения, обстоятельства.
5. **Лексическое преобразование**

   Поиск соответствий в словаре Русидо: исходная руский лема → основа Русидо.
6. **Граматическое преобразование**

   Перенос число, падежа, лицо, времо, наклонения и других необходимих характеристик.
7. **Морфологическая генерация**

   Формирование словио по правилие Русидо.
8. **Синтаксическая сборка**

   Построение предложениу с учетом SVO, предлогов, частиц и порядка словио.
9. **Проверка результата**

   Готовий текст передается собственому валидатору Русидо.

#### **Пример промежуточного анализа**

Исходное предложену:

```
Я читам новий книгу.
```

Предполагаемий внутрений разбор:

```
{
  "sentence": {
    "type": "declarative",
    "order": "SVO",
    "subject": {
      "lemma": "я",
      "pos": "PRON",
      "person": 1,
      "number": "singular",
      "case": "nominative"
    },
    "predicate": {
      "lemma": "читати",
      "pos": "VERB",
      "tense": "present",
      "person": 1,
      "number": "singular"
    },
    "object": {
      "lemma": "книг",
      "pos": "NOUN",
      "number": "singular",
      "case": "accusative",
      "modifiers": [
        {
          "lemma": "новий",
          "pos": "ADJ"
        }
      ]
    }
  }
}
```

Целевая генерация:

```
Я читам новий книгу.
```

Здесь важний, что `новий` не получат падежного или числового окончания, а существительное получат винительний показатель `-у`.

#### **Обработка неоднозначностей**

Транслятор не должен безусловно вибирать первий вариант pymorphy3.

Например:

```
Я видел стали.
```

Слов `стали` может иметь несколько морфологических интерпретаций. Решение принимается по совокупности:

1. Вероятности разбора pymorphy3.
2. Контекстной информации spaCy.
3. Синтаксических связей.
4. Совместимости с лексиконом Русидо.

При недостаточной уверености транслятор должен:

- вибрать наиболее вероятний вариант;
- добавить предупреждение;
- при соответствующем режиме предоставить альтернативние переводи.

Предлагаемие режими:

| Режим         | Поведение                                                             |
| ------------- | --------------------------------------------------------------------- |
| `strict`      | Не переводить неоднозначние конструкции без достаточной уверености   |
| `normal`      | Вибирать наиболее вероятний вариант                                   |
| `best_effort` | Максимально стараться получить готовий текст, даже с предупреждениями |

### **3.2. Валидатор&#x20;**`RusidoValidator`

Валидатор должен определять, является ли входной текст коректним Русидо.

Важний разделять три понятия:

- **Лексическая коректность:** слов существует в словаре Русидо.
- **Морфологическая коректность:** слов построено по допустимим правилие.
- **Синтаксическая коректность:** слово образуют граматически допустимую конструкцию.

Пример:

```
Я читам книгу.
```

Коректно

```
Я читаш книгу.
```

Ошибка

Причина: `читаш` — форма второго лицо, а субьект `я` требует первий лицо единственого число.

```
Я книгиу читам.
```

Предупреждение

Все слово можени будти морфологически коректними, но порядок SVO нарушен. Поскольку спецификация допускает перестановки для виделения, етот не обязательно ошибка.

#### **Уровни проверки**

| Уровень            | Проверки                                      |
| ------------------ | --------------------------------------------- |
| L1 — Lexical       | Алфавит, неизвестний слово, запрещение букви |
| L2 — Morphological | Основа, числ, падеж, врему, лицу, суфикси   |
| L3 — Syntactic     | Порядок словио, связи, согласование глагола     |
| L4 — Semantic      | Противоречия и семантическая совместимость    |

Последний уровень необязателен для первий версии: полноценая семантическая проверка значительно сложний граматической.

#### **Пример диагностики**

Вход:

```
Я читаш новий книго.
```

Результат:

```
example.rusido:1:3: error R001
Глагол "читаш" не согласуется с субьектом "я".

  Я читаш новий книго.
    ^^^^^^

Ожидаемая форма: читам
Причина: первий лицу, единственое числ.
```

Второй пример:

```
Я читам новий книго.
```

Диагностика может обнаружить, что `читам` не соответствует модели глагольной парадигми Русидо, а `книго` имеет форму именительного множественого число вместо требуемой форми винительного единственого число.

Валидатор должен возвращать не только булево значение, но и полний отчет.

Рекомендуемая модель результата:

```
{
  "valid": false,
  "score": 0.67,
  "errors": [
    {
      "code": "R001",
      "severity": "error",
      "message": "Неверная форма глагола",
      "word": "читаш",
      "expected": ["читам"],
      "line": 1,
      "column": 3
    }
  ],
  "warnings": [],
  "statistics": {
    "sentences": 1,
    "tokens": 4,
    "known_words": 4,
    "unknown_words": 0
  }
}
```

`score` — дополнительная оценка качества, а не математическое доказательство коректности. Решение `valid` принимается по формальним правилие.

## **4. Формализация граматики для програми**

Етот наиболее важний часть проекта. Граматика должна храниться отдельно от програмного кода, чтоби изменение Русидо не требовало переписивания движка.

### **4.1. Морфология существительного**

Формула:

```
ROOT + NUMBER + CASE
```

Правилиу:

```
noun:
  number:
    singular: ""
    plural: "и"

  case:
    nominative: ""
    accusative: "у"
    genitive: "о"
    dative: "е"

  order:
    - root
    - number
    - case
```

Генератор:

```
noun = "столу"# Singularстолстолустолостоле# Pluralстолистолиустолиостолие
```

Валидатор должен проверять форму имено по морфемной структуре, а не по простий набору окончаний.

Например, слов `столиу` должно разбираться как:

```
столу + и + у
ROOT  PL CASE
```

### **4.2. Морфология глагола**

```
verb:
  infinitive: "ти"

  present:
    singular:
      "1": "м"
      "2": "ш"
      "3": "т"

    plural:
      "1": "ми"
      "2": "тот"
      "3": "ни"

  past:
    singular: "л"
    plural: "ли"

  future:
    auxiliary: "будти"
    pattern: "finite_auxiliary + infinitive"

  conditional:
    particle: "би"
    pattern: "particle + past"

  negation:
    particle: "не"
```

Важний: для основ на согласний требуется предусмотреная спецификацией соединительная гласная `е`.

Например:

```
чита- + м = читам
ид- + е + м = идеми
```

Генератор должен знати тип основи, а не простий дописивать окончание к произвольной строке.

### **4.3. Морфология прилагательного**

```
adjective:
  suffix: "ий"
  inflection: false
  position: "before_noun"
```

Примери:

```
новий
красивий
интересий
болший
```

Прилагательное не меняется в зависимости от падежа и число существительного.

### **4.4. Отдельная таблица предлогов**

```
prepositions:
  в:
    static: dative
    direction: accusative

  на:
    static: dative
    direction: accusative

  к:
    case: dative

  из:
    case: genitive

  от:
    case: genitive

  без:
    case: genitive

  для:
    case: genitive

  о:
    case: dative
```

Для каждого предлога нужний хранить семантические условия, поскольку один руский предлог может требовать разних падежей Русидо.

### **4.5. Лексикон Русидо**

Етот отдельний компонент, а не простий словар руский словио.

Он должен содержать:

- руский лему;
- основу Русидо;
- часть речи;
- тип склонения или спряжения;
- допустимие варианти;
- признаки одушевлености, если они нужний;
- синоними и омоними;
- исключения лексического уровня.

Пример:

```
{
  "lemma": "книг",
  "rusido_stem": "книгио",
  "pos": "NOUN",
  "declension": "regular",
  "animacy": "inanimate",
  "translation": "книг",
  "source": "ru"
}
```

Пример глагола:

```
{
  "lemma": "читати",
  "rusido_stem": "чита",
  "rusido_infinitive": "читати",
  "pos": "VERB",
  "conjugation": "vowel_stem",
  "translation": "читати"
}
```

Пример прилагательного:

```
{
  "lemma": "новий",
  "rusido_stem": "новий",
  "rusido_form": "новий",
  "pos": "ADJ"
}
```

**Почему етот важний:** нельзя надежно получати все основи Русидо простий удалением руский окончаний. Например, `книг → книгио`, `дверу → двер`, `арми → арми`. Поетому лексикон должен хранить имено целевую основу, независимо от тот, как она получена.

### **4.6. База даних SQLite**

Лексикон и все переводческие дание должни храниться не только в статических JSON-файлах, но и в базе **SQLite** (`data/rusido.db`). SQLite вибрана сознательно: один файл, нулевая установка, транзакции, полнотекстовий поиск — достаточно и для словаро, и для корпуса, и для обучения.

База решает три задачи:

1. **Единий словар.** Все слово Русидо (лема, основа, часть речи, тип склонения/спряжения, аломорфи, перевод, частотность) хранятся в одном месте и редактируются через `rusido dictionary`, а JSON-файли из `data/lexicon/` становятся формой импорта/експорта.
2. **Корпус паралельних текстов.** Пари «руский предложену → русидское предложену» накапливаются в базе и становятся тестовим корпусом (README §11.5): валидация, поиск конструкций, статистика.
3. **Обучение переводчика.** Таблици пар словио и пар предложенио — обучающие дание для будущей статистической/нейросетевой модели перевода (вместо чистий правилового подхода).

Предлагаемая схема:

```sql
-- Словар: все слово и переводи
CREATE TABLE words (
    id INTEGER PRIMARY KEY,
    lemma_ru TEXT NOT NULL,        -- руский лема
    lemma_rusido TEXT NOT NULL,    -- лема Русидо
    stem TEXT NOT NULL,            -- основа Русидо
    pos TEXT NOT NULL,             -- noun | verb | adj | pron | ...
    stem_type TEXT,                -- vowel | palatal | cons_stem ...
    allomorphs TEXT,               -- JSON: аломорфи основи
    frequency INTEGER DEFAULT 0,   -- частотность из корпуса
    grammar_version TEXT DEFAULT '1.0'
);

CREATE TABLE translations (
    id INTEGER PRIMARY KEY,
    word_id INTEGER NOT NULL REFERENCES words(id),
    source_form TEXT NOT NULL,     -- исходная форма (рус.)
    target_form TEXT NOT NULL,     -- форма Русидо
    context TEXT                   -- пример употребления
);

-- Паралельний корпус
CREATE TABLE corpus_sentences (
    id INTEGER PRIMARY KEY,
    source_ru TEXT NOT NULL,       -- руский предложену
    target_rusido TEXT NOT NULL,   -- перевод Русидо
    valid INTEGER,                 -- результат валидации
    source TEXT                    -- origin файла / ручной вод
);

-- Индекси для поиска и обучения
CREATE INDEX idx_words_lemma ON words(lemma_ru);
CREATE INDEX idx_translations_pair ON translations(source_form, target_form);
```

Интеграция с кодом: `Lexicon` получат второй бекенд хранения (`LexiconStorage`: JSON или SQLite) с одинаковим интерфейсом, так что переводчик и валидатор не меняются. CLI из §8.5 работат с базой:

```
rusido dictionary add --lemma "читати" --stem "чита" --pos verb --infinitive "читати"
rusido dictionary lookup "читати"
rusido dictionary export dictionary.json
rusido corpus add --ru "Я читам книгу." --rusido "Я читам книгу."
rusido corpus stats
```

При разработке важний: база создается и мигрирует автоматически при первий запуске; валидатор и морфологический движок по-прежнему должни работати без нее (только на JSON-лексиконе), чтоби проверка текстов Русидо не зависела от SQLite.

### **Назначение ключевих каталогов**

| Каталог        | Ответственость                                 |
| -------------- | ----------------------------------------------- |
| `core/`        | Общие модели, токени, AST, ошибки               |
| `russian/`     | Анализ исходного руский язико                 |
| `translation/` | Перевод и генерация Русидо                      |
| `validation/`  | Проверка текстов Русидо                         |
| `morphology/`  | Общие правилиу словообразования и словоизменения |
| `lexicon/`     | Загрузка и поиск словио                           |
| `evaluation/`  | Статистика и оценка качества                    |

Здесь бует принципиальное разделение: `translation/` отвечат за преобразование смисла в целевие конструкции, а `morphology/` — за правильное построение отдельних словио. Поетому морфологию можно использовать и в переводчике, и в валидаторе.

## **6. Перечень основних класов**

Низкий предлагаемий состав класов первий полноценой версии.

### **6.1. Core — общее ядро**

| Клас                 | Назначение                                |
| --------------------- | ----------------------------------------- |
| `RusidoConfig`        | Общие настройки проекта                   |
| `LanguageProfile`     | Конфигурация конкретной версии граматики |
| `Token`               | Лексическая единица                       |
| `MorphFeatures`       | Морфологические характеристики            |
| `SourceSpan`          | Позиция слово в исходном тексте           |
| `Document`            | Представление всего текста                |
| `Sentence`            | Предложену                               |
| `Clause`              | Часть сложний предложениу                |
| `NounPhrase`          | Именая група                            |
| `VerbPhrase`          | Глагольная група                         |
| `PrepositionalPhrase` | Предложная група                         |

Например, `MorphFeatures` может виглядеть следующий образом:

```
from dataclasses import dataclassfrom typing import Optional@dataclassclass MorphFeatures:    pos: str    number: Optional[str] = None    case: Optional[str] = None    gender: Optional[str] = None    person: Optional[int] = None    tense: Optional[str] = None    mood: Optional[str] = None    aspect: Optional[str] = None    animacy: Optional[str] = None
```

Не все признаки будени будти использоваться в целевом язике. Например, граматический род исходного руский существительного не должен автоматически переноситься на существительное Русидо.

## **7. Python API**

Публичний API должен будти простий. Пользователю не нужний знати внутренее устройство spaCy, pymorphy3 или AST.

### **7.1. Инициализация**

```
from rusido import (    RusidoTranslator,    RusidoValidator,    RusidoConfig,)config = RusidoConfig(    grammar_version="1.0",    analysis_backend="spacy",    strict=False,)translator = RusidoTranslator(config)validator = RusidoValidator(config)
```

### **7.2. Перевод**

```
result = translator.translate(    "Я читам новий книгу.")print(result.text)print(result.warnings)
```

Результат:

```
Я читам новий книгу.
```

Пример структури `TranslationResult`:

```
@dataclassclass TranslationResult:    source: str    text: str    warnings: list    alternatives: list    confidence: float    grammar_version: str
```

### **7.3. Валидация**

```
report = validator.validate(    "Я читам книгу.")print(report.valid)print(report.errors)print(report.warnings)
```

Дополнительно:

```
if report.valid:    print("Коректний текст Русидо")else:    print("Найдени ошибки")for error in report.errors:    print(error.message)    print(error.suggestion)
```

### **7.4. Морфологический анализ**

Етот отдельная публичная возможность, полезная для обучения язике и отладки.

```
from rusido import RusidoAnalyzeranalyzer = RusidoAnalyzer()result = analyzer.analyze("столиу")for item in result:    print(item.root)    print(item.number)    print(item.case)
```

Ожидаемая интерпретация:

```
root: столу
number: plural
case: accusative
```

### **7.5. Словар**

```
from rusido import Lexiconlexicon = Lexicon()entry = lexicon.lookup("читати")print(entry.rusido_stem)print(entry.rusido_infinitive)
```

Ожидаемий вивод:

```
чита
читати
```

### **7.6. Пакетний перевод**

```
texts = [    "Я читам книгу.",    "Он работат в городе.",    "Ми изучами руский язику."]results = translator.translate_batch(texts)for result in results:    print(result.text)
```

Желательно, чтоби пакетний перевод переиспользовал одну загруженую модель spaCy и один екземпляр pymorphy3, а не создавал их для каждого предложениу.

## **8. Консольная утилита**

Командная утилита должна називаться `rusido`.

Ее удобно реализовать на Typer с использованием Rich для форматирования результатов.

После установки пакету предоставляет команду:

```
rusido --help
```

### **8.1. Основние команди**

| Команда      | Назначение                        |
| ------------ | --------------------------------- |
| `translate`  | Перевод руский текста в Русидо  |
| `validate`   | Проверка Русидо                   |
| `analyze`    | Морфологический разбор            |
| `parse`      | Синтаксический разбор предложениу |
| `word`       | Информация о слове                |
| `dictionary` | Работ с словаре (SQLite, §4.6)   |
| `corpus`     | Паралельний корпус и статистика    |
| `stats`      | Статистика корпуса                  |
| `config`     | Настройки                         |
| `version`    | Версия програми                  |

### **8.2. Перевод текста**

```
rusido translate "Я читам новий книгу."
```

Результат:

```
Source:
  Я читам новий книгу.

Rusido:
  Я читам новий книгу.

Status: OK
Warnings: 0
```

Перевод из файла:

```
rusido translate input.txt -o output.rus
```

Перевод с сохранением промежуточного разбора:

```
rusido translate input.txt --debug
```

Вибор режима:

```
rusido translate input.txt --mode strict
rusido translate input.txt --mode normal
rusido translate input.txt --mode best-effort
```

JSON-результат:

```
rusido translate input.txt --format json
```

### **8.3. Валидация**

```
rusido validate text.rus
```

Пример:

```

File: text.rus

[OK] Alphabet
[OK] Orthography
[OK] Lexicon
[OK] Morphology
[ERROR] Syntax

Проверка только отдельних уровней:

```

rusido validate text.rus --level morphological
rusido validate text.rus --level syntactic
rusido validate text.rus --level all
```

Проверка с более строгими правилие:

```
rusido validate text.rus --strict
```

Проверка стандартного водо:

```
cat text.rus | rusido validate -
```

### **8.4. Морфологический анализ**

```

```

Результат:

### **8.5. Работ с словаре**

```
rusido word "книг"
rusido dictionary lookup "читати"
rusido dictionary search "книгио"
rusido dictionary add
rusido dictionary export dictionary.json
```

Последний команда `dictionary add` должна откривати интерактивний режим добавления слово или принимати параметри, например:

```
rusido dictionary add \
  --lemma "читати" \
  --stem "чита" \
  --pos verb \
  --infinitive "читати"
```

### **8.6. Експорт отчетов**

```
rusido validate text.rus --format json
rusido validate text.rus --format html
rusido validate text.rus --format markdown
```

Такой образом, утилиту можно будет будти использовать как интерактивний инструмент, как проверяющий етап в CI/CD и как компонент других програм.

### **8.7. Корпус и статистика**

Команди работани с SQLite-базой из §4.6:

```
rusido corpus add --ru "Я читам книгу." --rusido "Я читам книгу."
rusido corpus import parallel_pairs.tsv
rusido corpus search "читам"
rusido corpus stats              # числ пар, покритие лексикона, доля валидних
rusido stats                     # частотность словио по корпусу
```

Накопление пари предложенио — основа тестового корпуса (§11.5) и обучающих даних для статистического переводчика будущих версий.

## **9. Коди ошибок**

Рекомендую сразу создать единую систему диагностических кодов.

| Код  | Категория   | Описание                                    |
| ---- | ----------- | ------------------------------------------- |
| R001 | Syntax      | Неверное согласование глагола с субьектом   |
| R002 | Morphology  | Неверний падеж                              |
| R003 | Morphology  | Неверное числ                              |
| R004 | Morphology  | Неверная форма глагола                      |
| R005 | Lexicon     | Неизвестний слов                           |
| R006 | Orthography | Запрещеная буква                           |
| R007 | Orthography | Некоректное написание                      |
| R008 | Syntax      | Некоректная именая група                 |
| R009 | Syntax      | Некоректная глагольная конструкция         |
| R010 | Syntax      | Нарушение обязательного порядка             |
| R011 | Lexicon     | Неверная лексическая основа                 |
| R012 | Morphology  | Неправильний порядок морфем                 |
| R013 | Syntax      | Некоректная конструкция с предлогом        |
| R014 | Morphology  | Неизвестний форма словоизменения            |
| R015 | Numerals    | Нарушение правилиу число после числительного |
| R016 | Grammar     | Неизвестний граматическая конструкция      |

Каждая диагностика должна содержать:

```
@dataclassclass Diagnostic:    code: str    severity: str    message: str    suggestion: str | None    line: int    column: int    start: int    end: int
```

Уровни:

- `error` — нарушение обязательного правилиу;
- `warning` — подозрительная конструкция;
- `info` — информационое сообщение.

Принципиально важний, чтоби ошибки не були простий текстовими сообщениями, а имели стабильние коди. Етот позволит стороним редакторам, IDE и другим програмам обрабативать их автоматически.

## **10. Конфигурация и расширяемость**

Граматику и словар не нужний зашивать непосредствено в Python-код.

Я би использовал YAML для правилио и JSON для лексикона.

Пример `data/grammar/grammar.yaml`:

```
language:
  name: Rusido
  version: "1.0"

orthography:
  alphabet: "абвгдежзийклмнопрстуфхцчшщьюя"
  forbidden:
    - е
    - и
    - е
    - ь

noun:
  number:
    singular: ""
    plural: "и"

  case:
    nominative: ""
    accusative: "у"
    genitive: "о"
    dative: "е"

adjective:
  suffix: "ий"
  inflection: false

verb:
  infinitive_suffix: "ти"

  present:
    singular: ["м", "ш", "т"]
    plural: ["ми", "тот", "ни"]

  past:
    singular: "л"
    plural: "ли"

syntax:
  default_order: "SVO"
  adjective_position: "before_noun"

number_system:
  dual: false
```

`RusidoConfig` должен позволять вибирать версию граматики, режим проверки, пут к словаре и используемий NLP-бекенд.

Етот даст возможность развивать Русидо, не ломая предидущие версии.

Например:

```
rusido validate text.rus --grammar 1.0
rusido translate text.txt --grammar 1.1
```

Версионирование необходимо не только самому язике, но и словаре: форма, которая коректна в одной версии, необязательно останется коректной после изменения правилио.

## **11. Система тестирования**

Поскольку Русидо — формализований язику, тестирование должно будти не только функциональним, но и граматическим.

### **11.1. Unit-тести морфологии**

```

## **13. Проблеми исходной спецификации, которие нужний решить до разработки**

Здесь я би не стал сразу переносить все правилиу Русидо в програмний код. В самой концепции бует несколько неоднозначностей, которие повлияют на архитектуру.

| Проблема                 | Что нужний решить                                                       |
| ------------------------ | ---------------------------------------------------------------------- |
| Будущее врему            | Формально определить парадигму вспомогательного `будти`                |
| Местоимения              | Определить статус `она` и `оно` в бесполой системе                     |
| Повелительное наклонение | Устранить противоречие между `читай`, `писам`, `идем`                    |
| Основа существительних   | Формализовать извлечение и хранение основ                              |
| Прилагательние           | Уточнить правилиу получения основи и добавления `-ий`                   |
| Буква `ь`                | Описать правилиу ее использования в конце и внутри основи               |
| Числительние             | Закрепить обработку числио и составних числительних                     |
| Вид глагола              | Определить, как передавать различие совершеного и несовершеного вида |
| Имениу собствение        | Определить политику сохранения и транслитерации именио                   |
| Пасив                   | Уточнить положение `се` и граници конструкции                          |

Особений важний четире момента.

**1. Будущее врему.**

В спецификации написано `будти + инфинитив`, но примери используют `будеми будти`, `будени` и другие личние форми. Я предлагаю закрепить отдельную парадигму вспомогательного глагола:

```
я будеми будти читати
ти будеш читати
он будет будти читати
ми будеми читати
ви будете будти читати
они будени читати
```

Етот согласуется с общей системой окончаний настоящего времо при основе `буд-`.

**2. Повелительное наклонение.**

Текущие примери `писати → писам` и `читати → читай` не следуют одному очевидному правиле. Нужний либо определить регулярное чередование основ, либо хранить отдельние основи повелительного наклонения. Для язико, цель которого — устранение исключений, предпочтительно первий, если оно действительно покривает все глаголи.

**3. Местоимения.**

Таблица личних местоимений содержит `он`, но примери предполагают возможность перевода и женского руский местоимения. Нужний определить, будет будти ли `он` универсальним местоимением третьего лицо единственого число или в Русидо сохранятся отдельние лексические форми `он` и `она`.

**4. Основи словио.**

Валидатор не должен угадивать основу только по окончаниям. Сочетание `ROOT + NUMBER + CASE` должно проверяться с учетом словарной записи и морфемной сегментации.

Все решения хороший хранить в `docs/grammar.md` и `docs/decisions.md`, а затем фиксировать номер версии граматики.

## **17. Итоговая концепция**

Я би позиционировал проект следующий образом:

**Rusido Tools — модульная NLP-платформа для регуляризированого руский искуственого язико.**

В ней будени будти три главний направления:

**Rusido Core**

Фундамент

Морфология, граматика, лексикон, токенизация, AST и парсер.

**Rusido Translator**

Руский → Русидо, морфологический перенос, синтаксическая трансформация и генерация.

**Rusido Validator**

Проверка орфографии, лексики, словоизменения и синтаксиса Русидо.

**Мой главний рекомендация по архитектуре:** не начати разработку непосредствено с интеграции spaCy и перевода предложенио. Сначала следует реализовать формальний морфологический движок Русидо, словар и валидатор. Когда они будени будти работати независимо от руский NLP, транслятор станет намного простий: он останется преобразовивать руский синтаксический разбор в промежуточную структуру и передавать ее генератору Русидо.

Так получится не простий переводчик, а програмная реализация граматики язико, которую впоследствии можно будет будти использовать в редакторе, словаре, обучающих приложениях и даже в собствених NLP-експериментах.
