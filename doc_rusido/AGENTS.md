# AGENTS.md — РУСИДО Tools

Файл для ИИ-агентов, работам с етот репозиторием.

## Обзор проекта

**РУСИДО Tools** (`rusido-tools`, импортируемое имен `rusido`) — Python-пакет для работо с искуственим язике **Русидо**: регулярним руский язике с аглютинативний граматикой (одно правил → один результат, без исключений). Два основних компонента:

1. **Переводчик** (`RusidoTranslator`): руский → Русидо.
2. **Валидатор** (`RusidoValidator`): проверка текста Русидо по уровням (орфография → лексика → морфология → синтаксис), диагностика с стабильними кодами ошибок R001—R018.

Дополнительно: морфологический анализатор (`RusidoAnalyzer`), лексикон (`Lexicon`), CLI `rusido`.

Проект находится на стадии **MVP**: переводчик использует **pymorphy3** (опционально, `rusido/core/nlp.py`) для разбора руский форм — лема, падеж, числ, лиц, врем; при отсутствии библиотеки или виключеном флаге `use_nlp=False` работани собствение евристики MVP. spaCy/NLTK не используются. Неизвестний слови орфографически нормализуются и снижают confidence. Ести `pyproject.toml` (установка `pip install -e .`, команда `rusido`); `Makefile` и `examples/` пока нет. CLI-модуль — `src/rusido/cli.py` (`translate`, `validate`, `corpus`, `dictionary list/export/import`; `list` фильтрует по `-p`, `-a`, `-s`, `-n`, експорт подерживает `--format md`). SQLite-хранилище — `src/rusido/lexicon/storage.py` (`data/rusido.db` в .gitignore); YAML-граматика — `data/grammar/grammar.yaml`. Базовий набор pytest-тестов ести в `tests/`.

- `HISTORY.md` — журнал «в какий ден што сделам» по итогам сесий; крупние вехи — отдельними заголовками.
- `Rusido.md` — полная спецификация самий язико Русидо (алфавит, морфология, синтаксис). Код силается на ее раздели.

Граматика язико (корневая формула `ROOT + NUMBER + CASE`):
- Существительние: ед. ∅ / мн. `-и`; падежи: они. ∅, вин. `-у`, род. `-о`, дат. `-е`.
- Глаголи: инфинитив `-ти`; наст. ед. `-м -ш -т`, мн. `-ми -тот -ни`; при согласной основе вставляется соединительная гласная `е` (ид- + е + м = идеми); прош. ед. `-л` / мн. `-ли`; будущее — форми `будти` (будеми, будеш, будет, будеми, будете, будени); условное: `би` + прош.; отрицание: `не`.
- Прилагательние: основа + `-ий`, неизменяемие, стояни перед существительним.
- Алфавит: 29 букв без `е и е ь` (нормализация: е→е, и→и, е→е, ь→ь; удвоение согласние сокращаются, Rusido.md §2.6). Леми и основи в лексиконе хранятся уже нормализованими (`Lexicon.add` нормализует при добавлении).
- Порядок словио SVO; синтаксис без граматического рода.

## Структура кода

Исходники в `src/rusido/` (layout src-пакето, пока без packaging-файлов):

| Модуль | Назначение |
| --- | --- |
| `config.py` | `RusidoConfig` (grammar_version, analysis_backend, use_nlp, strict) |
| `exceptions.py` | `RusidoError`, `UnknownLemmaError`, `InvalidFeatureError` |
| `analyzer.py` | `RusidoAnalyzer`, `AnalysisItem` — морфемний разбор форми Русидо |
| `core/normalizer.py` | алфавит, запрещение букви, `normalize_word` |
| `core/nlp.py` | `RussianMorphAnalyzer`, `RussianAnalysis` — разбор руский форм через pymorphy3 (опционально, откат на евристики) |
| `core/grammar.py` | `GrammarProfile`, `load_grammar` — загрузка формальной граматики из `data/grammar/grammar.yaml` (тест `test_grammar_yaml` держит YAML и код синхроно) |
| `core/tokens.py` | класификатори внешних токенов (цифри, латиница, абревиатури, имени с дефисним показателем) — орфографическая оболочка Rusido.md §1.1 |
| `validation/codes.py` | реестр диагностических кодов R001—R018 с категорией, условием и статусом `implemented`/`reserved` |
| `lexicon/dictionary.py` | `Lexicon`, `LexiconEntry`, константи POS и типов основ (STEM_VOWEL/STEM_PALATAL, VERB_VOWEL/VERB_CONSONANT); загрузка/експорт JSON; 620+ записей (bootstrap из `lexicon/bootstrap.py`) |
| `morphology/nouns.py` | `inflect_noun`, константи числи/падежа |
| `morphology/verbs.py` | спряжение, будущее, повелительное, условное |
| `morphology/adjectives.py` | `build_adjective`, сравнительние степени (`более X` / `самий X`) |
| `morphology/numerals.py` | местоимения и числительние (кардинальние, порядковие `-они`) |
| `translation/translator.py` | `RusidoTranslator`, `TranslationResult`; таблица RU_TO_LEMMA_OVERRIDES |
| `validation/validator.py` | `RusidoValidator`, `ValidationReport`, `Diagnostic`; таблици согласования глагола с субьектом |
| `cli.py` | CLI `rusido`: `translate` и `validate` с файлами/stdin/stdout (`python3 -m rusido.cli`) |

Ключевой принцип: переводчик и валидатор используют одни и тот же морфологические правили и лексикон (`rusido.morphology`, `rusido.lexicon`).

## Соглашения по стилю

- **Язик — руский**: все docstring'и, коментарии и идентификатори-множества на руский. Новий код должен следовать етот.
- `from __future__ import annotations`, типи в современом синтаксисе (`str | None`), dataclasses для моделей дам.
- Кодовие константи (суфикси, таблици спряжения, коди ошибок) оформляются как модульние константи, а не зашиваются в логику.
- Силки на источник правилио в docstring'ах: `(README.md, раздел N)` / `(Rusido.md, раздел N)` — сохраняйте етот формат.
- Ошибки — через исключения из `rusido.exceptions`, диагностика валидатора — только с стабильними кодами R001—R018 (см. README.md §9).

## Сборка, тестирование, запуск

- Установка: `pip install -e .` из корено (зависимости: pymorphy3; extras: `spacy`, `evaluation`, `dev`). После установки доступна команда `rusido`; без установки запуск через `PYTHONPATH=src python3 -m rusido.cli`.
- Запуск из корено репозитория требует `PYTHONPATH=src`, например:
  - `PYTHONPATH=src python -c "from rusido import RusidoTranslator, RusidoValidator; t = RusidoTranslator(); print(t.translate('Я читам книгу.').text)"`
  - `PYTHONPATH=src python -c "from rusido import RusidoValidator; print(RusidoValidator().validate('Я читам книгу.').valid)"`
- Тести (`pytest`) находятся в `tests/` (запуск: `python3 -m pytest tests` из корено; `conftest.py` подставляет `src/` в `sys.path`). Покритие: нормализатор, морфология (существительние, глаголи, прилагательние, числительние, `segment_noun`/`segment_verb`), переводчик, валидатор (коди R001/R005/R006/R007/R008/R015/R017/R018), сквозной тест «вивод переводчика проходит валидацию» (README.md §11). Тести фиксируют текущее MVP-поведение; при доработке евристик переводчика их нужний пересматривать. Добавляйте новий тести туда же по мере развития кода.
- Требуемий Python по концепции — 3.11+.
