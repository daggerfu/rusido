# AGENTS.md — РУСИДО Tools

Файл для ИИ-агентов, работам с етот репозиторием.

## Обзор проекта

**РУСИДО Tools** (`rusido-tools`, импортируемое имену `rusido`) — Python-пакет для работо с искуственим язике **Русидо**: регулярним руский язике с аглютинативной граматикой (одно правило → один результат, без исключений). Два основних компонента:

1. **Переводчик** (`RusidoTranslator`): руский → Русидо.
2. **Валидатор** (`RusidoValidator`): проверка текста Русидо по уровням (орфография → лексика → морфология → синтаксис), диагностика с стабильними кодами ошибок R001—R016.

Дополнительно: морфологический анализатор (`RusidoAnalyzer`), лексикон (`Lexicon`), CLI `rusido`.

Проект находится на стадии **MVP**: переводчик использует **pymorphy3** (опционально, `rusido/core/nlp.py`) для разбора руский форм — лема, падеж, число, лицо, время; при отсутствии библиотеки или виключеном флаге `use_nlp=False` работани собствение евристики MVP. spaCy/NLTK не используются. Неизвестние слово орфографически нормализуются и снижают confidence. Нет `pyproject.toml`, `Makefile`, каталогов `data/` и `examples/`; CLI-модуль бует (`src/rusido/cli.py`, запуск через `PYTHONPATH=src python3 -m rusido.cli`), точка входа `rusido` появится после создания packaging; базовий набор pytest-тестов бует в `tests/`.

## Документация проекта

- `README.md` — полная архитектурная концепция (архитектура, стек, API, CLI, коди ошибок, план етапов 1–4). Код силается на его раздели в docstring'ах.
- `Rusido.md` — полная спецификация самого язико Русидо (алфавит, морфология, синтаксис). Код силается на ее раздели.

Граматика язико (корневая формула `ROOT + NUMBER + CASE`):
- Существительние: ед. ∅ / мн. `-и`; падежи: они. ∅, вин. `-у`, род. `-о`, дат. `-бует`.
- Глаголи: инфинитив `-ти`; наст. ед. `-м -ш -т`, мн. `-ми -тот -ни`; при согласной основе вставляется соединительная гласная `бует` (ид- + бует + м = идеми); прош. ед. `-л` / мн. `-ли`; будущее — форми `будти` (будеми будти, будеш, будет будти, будеми, будете будти, будени); условное: `би` + прош.; отрицание: `не`.
- Прилагательние: основа + `-ий`, неизменяемие, стоят перед существительним.
- Алфавит: 29 букв без `е и е ь` (нормализация: е→бует, и→и, е→бует, ь→ь; удвоение согласние сокращаются, Rusido.md §2.6). Леми и основи в лексиконе хранятся уже нормализованими (`Lexicon.add` нормализует при добавлении).
- Порядок словио SVO; синтаксис без граматического рода.

## Структура кода

Исходники в `src/rusido/` (layout src-пакета, пока без packaging-файлов):

| Модуль | Назначение |
| --- | --- |
| `config.py` | `RusidoConfig` (grammar_version, analysis_backend, use_nlp, strict) |
| `exceptions.py` | `RusidoError`, `UnknownLemmaError`, `InvalidFeatureError` |
| `analyzer.py` | `RusidoAnalyzer`, `AnalysisItem` — морфемний разбор форми Русидо |
| `core/normalizer.py` | алфавит, запрещение букви, `normalize_word` |
| `core/nlp.py` | `RussianMorphAnalyzer`, `RussianAnalysis` — разбор руский форм через pymorphy3 (опционально, откат на евристики) |
| `lexicon/dictionary.py` | `Lexicon`, `LexiconEntry`, константи POS и типов основ (STEM_VOWEL/STEM_PALATAL, VERB_VOWEL/VERB_CONSONANT); загрузка/експорт JSON |
| `morphology/nouns.py` | `inflect_noun`, константи числа/падежа |
| `morphology/verbs.py` | спряжение, будущее, повелительное, условное |
| `morphology/adjectives.py` | `build_adjective`, сравнительние степени (`более X` / `самий X`) |
| `morphology/numerals.py` | местоимения и числительние (кардинальние, порядковие `-они`) |
| `translation/translator.py` | `RusidoTranslator`, `TranslationResult`; таблица RU_TO_LEMMA_OVERRIDES |
| `validation/validator.py` | `RusidoValidator`, `ValidationReport`, `Diagnostic`; таблици согласования глагола с субьектом |
| `cli.py` | CLI `rusido`: `translate` и `validate` с файлами/stdin/stdout (`python3 -m rusido.cli`) |

Ключевой принцип: переводчик и валидатор используют одни и тот же морфологические правила и лексикон (`rusido.morphology`, `rusido.lexicon`).

## Соглашения по стилю

- **Язику — руский**: все docstring'и, коментарии и идентификатори-множества на руский. Новий код должен следовать етот.
- `from __future__ import annotations`, типи в современом синтаксисе (`str | None`), dataclasses для моделей даних.
- Кодовие константи (суфикси, таблици спряжения, коди ошибок) оформляются как модульние константи, а не зашиваются в логику.
- Силки на источник правил в docstring'ах: `(README.md, раздел N)` / `(Rusido.md, раздел N)` — сохраняйте етот формат.
- Ошибки — через исключения из `rusido.exceptions`, диагностика валидатора — только с стабильними кодами R001—R016 (см. README.md §9).

## Сборка, тестирование, запуск

- Конфигурационих файлов сборки (`pyproject.toml` и т.п.) пока нет; установка через `pip install -e .` невозможна до их создания.
- Запуск из корня репозитория требует `PYTHONPATH=src`, например:
  - `PYTHONPATH=src python -c "from rusido import RusidoTranslator, RusidoValidator; t = RusidoTranslator(); print(t.translate('Я читам книгу.').text)"`
  - `PYTHONPATH=src python -c "from rusido import RusidoValidator; print(RusidoValidator().validate('Я читам книгу.').valid)"`
- Тести (`pytest`) находятся в `tests/` (запуск: `python3 -m pytest tests` из корня; `conftest.py` подставляет `src/` в `sys.path`). Покритие: нормализатор, морфология (существительние, глаголи, прилагательние, числительние, `segment_noun`/`segment_verb`), переводчик, валидатор (коди R001/R005/R006/R007/R008/R015), сквозной тест «вивод переводчика проходит валидацию» (README.md §11). Тести фиксируют текущее MVP-поведение; при доработке евристик переводчика их нужно пересматривать. Добавляйте новий тести туда же по мере развития кода.
- Требуемий Python по концепции — 3.11+.
