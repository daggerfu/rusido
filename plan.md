## 2. Что будет сделано

### Этап 1. Evaluation и переводчик v1
- Снятие синкретизма падежей pymorphy3 по контексту предложения (сейчас «книги» → род. ед. по первой гипотезе; варианты — частотный словарь или анализ всего токена-контекста).
- Фиксация в спецификации перевода русской связки «будет» (NLP и эвристика сейчас расходятся).
- Перевод местоимений «она/оно» → `он` (D по §5.1); модальные и служебные глаголы («хотеть», «мочь» — частично в лексиконе).
- spaCy-бэкенд (`ru_core_news_sm`): синтаксис, разрешение омонимии, выбор подлежащего/объекта.
- Режимы strict / normal / best_effort с количественными порогами уверенности.

### Этап 2. Валидатор v1
- Управление предлогов (R002/R003/R013): `в дому` для направления, `из домо` для источника.
- Реализация зарезервированных кодов (R009—R014, R016) либо их снятие с публикацией критериев.
- `score` в отчёте по определённой формуле; экспорт JSON.
- Развитие проверок сложных предложений (несколько подлежащих, придаточные §8.9).

### Этап 3. CLI и грамматика как данные
- Полный CLI по README §8: `analyze`, `word`, `stats`, `config`, `version`; флаги `--mode`, `--level`, `--format json`, `--grammar`; Rich-вывод (опционально).
- Флаг `--grammar` для выбора YAML-профиля в CLI.
- Модуль `evaluation/`: корпус Русидо, BLEU, частотный анализ.
- Примеры в `examples/`, документация `docs/`.

### Этап 4. Качество и сопровождение
- CI (GitHub Actions): pytest на 3.x, установка через pyproject.toml.
- Нижние границы версий pymorphy3 в зависимостях.
- Property-тесты морфологии (все сгенерированные формы валидны).
- ruff, mypy; публикация на PyPI после стабилизации грамматики v1.0.
