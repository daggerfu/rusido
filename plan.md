## 2. Что будет сделано

### Этап 1. Закрытие спецификации (БЛОКЕР — до всего остального)
- Решить противоречия Rusido.md: алломорфы глаголов (`писати→пиши`, `люблим`), лемма будущего (`будти` vs `быти`), система числительных (`однадек` vs `однанадек`, разряды, 600/7000), `нет + род. п.`, статус связки `ест`, правила для `ь`.
- Формализовать неиспользуемые коды ошибок R002–R004, R009–R014, R016; развести двойное значение R007.
- Определить слепые пятна: имена собственные, цифры, КАПС/регистр, заимствования, пунктуация, перестановки порядка слов.
- Завести `docs/decisions.md` с фиксацией решений и версиями грамматики.

### Этап 2. Грамматика как данные
- [x] `pyproject.toml` + установка `pip install -e .`, entry point `rusido`, зависимости (pymorphy3, extras: spacy/evaluation/dev).
- [x] SQLite-база (`data/rusido.db`, README §4.6): `SqliteStorage` (words/translations/corpus_sentences), CLI `corpus add/search/stats`, `dictionary import/export`; валидатор и морфология от базы не зависят.
- [x] Морфология принимает `GrammarProfile` (nouns/verbs/adjectives + сегментация валидатора); кастомный YAML реально меняет формы (тест `test_custom_grammar_version_changes_output`). Осталось: флаг `--grammar` в CLI.
- [ ] CI (GitHub Actions).
- Вынести суффиксные таблицы и правила в `data/grammar/grammar.yaml`; загрузка через `RusidoConfig.grammar_version`.
- Расширить лексикон до 500+ записей (критерий MVP README §15) с поддержкой алломорфов.

### Этап 3. Переводчик v1
- spaCy-бэкенд (`ru_core_news_sm`): синтаксис, разрешение омонимии (`стали`), выбор подлежащего/объекта.
- Режимы strict / normal / best_effort с количественными порогами уверенности; альтернативные переводы в `TranslationResult`.
- Перевод контекстом целых предложений (снятие синкретизма падежей: «книги» им.мн. vs род.ед.).
- Обработка неизвестных слов: предупреждения в `TranslationResult.warnings` (сейчас не заполняется).

### Этап 4. Валидатор v1
- Управление предлогов (R002/R003/R013): `в домо` для направления, `из домо` для источника.
- Полная диагностика с позициями (column/start/end) и подсветкой фрагмента (формат README §3.2).
- Проверка всех сказуемых предложения (сейчас одно), сложные предложения.
- `score` в отчёте по определённой формуле; экспорт JSON.

### Этап 5. CLI и Evaluation
- Полный CLI по README §8: `analyze`, `parse`, `word`, `dictionary`, `stats`, `config`, `version`; флаги `--mode`, `--level`, `--format json/html/markdown`, `--grammar`; Rich-вывод (опционально).
- Модуль `evaluation/`: корпус Русидо, BLEU через NLTK, частотный анализ.
- Примеры в `examples/`, документация `docs/`.

### Этап 6. Качество и сопровождение
- Покрытие тестами валидатора позициями, анализатора, сериализации лексикона; property-тесты морфологии (гипотеза: все сгенерированные формы валидны).
- Удалить `.DS_Store` из истории, линтер (ruff), типизация (mypy).
- Публикация пакета (PyPI) после стабилизации грамматики v1.0.

## 3. Критерии выхода из MVP (следующая веха — v0.2)
1. Противоречия спецификации закрыты, `docs/decisions.md` заведён.
2. Грамматика загружается из YAML, `grammar_version` работает.
3. Лексикон ≥ 500 записей.
4. Переводчик работает в режиме normal без spaCy и в полном режиме со spaCy.
5. Все коды R001–R016 определены и реализованы с документированными критериями.
6. Пакет устанавливается через pip, CLI `rusido` доступен как команда.
