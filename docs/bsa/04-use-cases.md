## UC-1. Перевести русский текст в Русидо

**Актор:** Пользователь (через CLI или API). **Связи:** US-A1–A5.

**Предусловия:** пакет установлен (`pip install -e .`), команда `rusido` доступна;
опционально установлен pymorphy3 (иначе эвристики).

**Основной поток:**
1. Пользователь передаёт текст: `rusido translate file.txt` или stdin, либо
   `RusidoTranslator().translate(text)` из Python.
2. Система разбивает текст на строки и токены, сохраняя пунктуацию и пробелы.
3. Для каждого слова: NLP-разбор (лемма/падеж/число/лицо/время) или эвристики;
   обращение в лексикон; применение морфологических правил Русидо.
4. Система собирает текст Русидо, считает confidence (доля известных слов).
5. Вывод: переведённый текст в stdout; предупреждения о неизвестных словах — в stderr
   (CLI) / `TranslationResult.warnings` (API).

**Альтернативные потоки:**
- 3a. Слово из закрытого служебного списка §2.2 → переводится словарно
  (`RU_TO_LEMMA_OVERRIDES`, D-004).
- 3b. Слово неизвестно → орфонормализуется, добавляется warning, confidence снижается.
- 3c. `use_nlp=False` / pymorphy3 не установлен → только эвристики MVP.

**Постусловия:** вывод проходит валидацию (сквозной тест, README §11); warnings
не маскируют результата (код выхода 0, предупреждения отделены).

## UC-2. Проверить текст Русидо

**Актор:** Пользователь. **Связи:** US-B1–B5, T-`test_validator.py`.

**Предусловия:** текст в кодировке UTF-8; лексикон загружен (по умолчанию 621 запись).

**Основной поток:**
1. `rusido validate file.txt [--strict]` или `RusidoValidator().validate(text)`.
2. Уровень орфографии: запрещённые буквы (R006), символы вне алфавита (R018),
   удвоенные согласные (R007) — с suggestion.
3. Внешние токены §1.1 пропускаются без R005–R007/R018.
4. Уровень лексики: словарные леммы/канонические формы (R005 с suggestion).
5. Уровень морфологии: разбор ROOT+NUMBER+CASE, глагольных форм, `-ий`, `-им`.
6. Уровень синтаксиса: R001 (согласование, каждое сказуемое), R015 (число после
   числительного, включая цифровую запись §6.7), R008 (прилагательное + существительное).
7. Отчёт `ValidationReport`: valid, errors/warnings с позициями
   (line/column/start/end), число предложений и токенов; код выхода 0/1/2.

**Альтернативные потоки:**
- 2a. Запрещённая буква, но нормализованная форма известна → только R006 (без R005).
- 6a. Омонимия существительное/глагол («брате») → приоритет некодинитивной
  падежной формы, R001 не выдаётся (D-014).
- 7a. `--strict` и нет финальной пунктуации → warning R017.

**Постусловия:** все коды из отчёта существуют в реестре `validation/codes.py`.

## UC-3. Разобрать слово по морфемам

**Актор:** Лингвист. **Связи:** US-C1.

**Поток:** ввод слова Русидо → `RusidoAnalyzer` возвращает `AnalysisItem`:
корень/основа (с учётом алломорфов §7.1.1), суффиксы числа/падежа/времени/лица,
каноническая форма. Неизвестное слово → пустой разбор без ошибки.

## UC-4. Пополнить лексикон / работать с корпусом

**Актор:** Лингвист/Пользователь. **Связи:** US-C3, C4.

**Поток:**
1. `Lexicon.add(lemma, stem, pos)` — лемма и основа нормализуются (ё/ы/э/ъ,
   удвоенные согласные); запись доступна переводчику и валидатору немедленно.
2. `dictionary import words.json` / `export --format md` — обмен словарём
   (roundtrip JSON покрыт тестами).
3. `corpus add "рус" "русидо"` / `search запрос` / `stats` — параллельный корпус
   в SQLite, поиск регистронезависим.

**Постусловия:** сериализация обратима (`to_json`/`from_json`, T-roundtrip).

## UC-5. Экспериментировать с грамматикой (YAML-профиль)

**Актор:** Лингвист. **Связи:** US-C2.

**Поток:** правка `data/grammar/grammar.yaml` (окончания, алфавит, эпентеза) →
`load_grammar` → морфология и валидатор строят формы по профилю;
`grammar_version` отражается в результатах перевода.

**Постусловия:** `test_grammar_yaml.py` держит YAML и кодовые константы синхронно.

## UC-6. Измерить качество перевода (цель v0.2)

**Актор:** Исследователь. **Связи:** US-D5.

**Поток:** параллельный корпус → `evaluation/` → BLEU против эталона +

фиксируется в `02-to-be.md` §4 как baseline для регрессий.
