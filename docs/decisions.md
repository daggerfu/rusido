# DECISIONS — журнал решений по языку Русидо

Формат: номер, дата, контекст, решение, обоснование, следствия. Каждое решение
привязано к версии грамматики (`data/grammar/grammar.yaml`, поле `version`).
Журнал ведётся по рекомендации README §13: решения фиксируются здесь, а не
размазываются по коду и спецификации.

Текущая версия грамматики: **1.0**.

---

## D-001. Ударение не регламентируется (2026-11-15, §2.5)

**Контекст.** Первоначально: «ударение всегда на предпоследнем слоге, при
словоизменении не меняется». Противоречие: при агглютинации (`стол → столу →
столиу`) предпоследний слог смещается, а для односложных слогов правило не
определено. Примеры (`кни́га → книг`) фактически показывали усечение, а не
перенос ударения.

**Решение.** Ударение не является различительным признаком Русидо. Оно
сохраняется от исходного русского слова и при словоизменении смещается только
вместе со слогом основы; аффиксы безударные.

**Обоснование.** (1) Фиксированное предпоследнее ударение несовместимо с
агглютинацией без постоянного «перескока» ударения. (2) Ударение в письменном
языке не кодируется, поэтому не может быть проверяемым правилом — а валидатор
обязан проверять всё, что заявлено. (3) Сохранение русского ударения
поддерживает цель «узнаваемость русского слова».

**Следствия.** Валидатор ударение не проверяет. Правило фонетики остаётся
единственным необязательным к реализации.

## D-002. `он` — универсальное безродовое местоимение (2026-11-15, §5.1)

**Контекст.** В таблице личных местоимений 3-е лицо ед. ч. — только `он`, но в
примерах встречалась `она`. Язык заявлен безродовым, но экспонентные суффиксы
`-ец/-ица` (§3.2) намекают на род.

**Решение.** `он` переводит русские `он`, `она`, `оно`. Отдельных форм нет.
Суффиксы `-ец/-ица` трактуются как лексические (образование названий лиц) и
согласовательного рода не создают.

**Обоснование.** Два принципа конфликтуют: «нет грамматического рода» и
«русские корни сохраняются». Род как категория согласования дешевле удалить
полностью — он не несёт смысловой нагрузки в 3-м лице, а его сохранение
потребовало бы трёх местоимений и правил выбора. Узнаваемость страдает
незначительно: контекст восстанавливает референт.

**Следствия.** Переводчик заменяет `она/оно` → `он` (тест на это есть в
`tests/test_translator.py` косвенно, через инвариантность `он`). Образцы
спецификации используют только `он`.

## D-003. Будущее время — спрягаемый вспомогательный глагол (2026-11-15, §7.4)

**Контекст.** Заявлено `будти + инфинитив`, но примеры использовали `будем`,
`будени`. README §4.2 вообще называло вспомогательный глагол `быти`.

**Решение.** Будущее = личная форма `буд-` + инфинитив:
`будем/будеш/будет/будеми/будете/будени`. Лемма — `будти` (не `быти`).
Парадигма строится общим правилом §7.2 для основ на согласный (`буд + е + м`).

**Обоснование.** Аналитическая конструкция с инвариантным вспомогательным
(`будти` во всех лицах) хуже: теряется согласование с субъектом, а язык
сохраняет личное согласование в настоящем и прошедшем. Единая парадигма
`буд-` — это ровно одно дополнительное правило (лексическая основа), а не
новая модель. Имя `будти` выбрано, чтобы не конфликтовать с инвариантной
связкой `ест` и русским «быть/бить».

**Следствия.** В лексиконе основа `быть` = `буд` (исправлено с ошибочного
`бу`). Связка «есть (обладать)» и глагол «есть (кушать)» разведены:
связка — инвариантная `ест`, пищевой глагол пока не введён (открытый вопрос,
см. D-012).

## D-004. Служебные слова с уникальными формами — закрытый словарный список (2026-11-15, §2.2)

**Контекст.** `что → што`, `чтобы → штобы`, `который → кторий`, `ещё → ешо`
не выводятся правилами орфографии (`что` по правилам дало бы `что`).

**Решение.** Признан закрытый список служебных слов, формы которых
фиксируются словарём и не выводятся. Список: `што`, `штобы`, `кторий`, `ешо`,
`етот`. Других слов такого типа не вводить без записи сюда.

**Обоснование.** Регулярная замена `ч → ш` сделала бы правило орфографии
зависимым от позиции (исключение), что хуже малого явного списка. Принцип
«одно правило → один результат» нарушается либо правилом с исключениями, либо
словарём; словарь честнее и проверяемее.

**Следствия.** Валидатор принимает эти формы через лексикон. Переводчик
содержит их как инвариантные записи. Новые аналоги — только через запись
в этот журнал.

## D-005. Сотни и тысячи — закрытый словарный список (2026-11-15, §6.4)

**Контекст.** Система разрядов (`однтис`, `двесто`) нерегулярна: кластеры
`днт`, `сто`-в-`двесто`, за пределами 5 в разряде формы не определены (600?
7000?).

**Решение.** Формы сотен и тысяч (1–5 в каждом разряде) — закрытый словарный
список. За его пределами число пишется цифрами или описательно. Расширение
списка — решение отдельной версии грамматики.

**Обоснование.** Композиция разрядов в лоб даёт нерегулярные кластеры согласных
и требует эпентезных правил, которые сейчас не описаны. Закрытый список из 10
слов покрывает типичное употребление и честно декларирует ограничение.

**Следствия.** `numerals.py` хранит разряды как словари; код R015 согласования
числительных работает только по списку. Открытый вопрос перенесён из README §13
в статус «решено для 1.0, пересмотреть в 1.1».

## D-006. Эпентеза `е` распространена на прошедшее время (2026-11-15, §7.3)

**Контекст.** Соединительная `е` описана только для настоящего (`ид + е + м =
идем`). Прошедшее основы на согласный давало бы `идл`.

**Решение.** Единое правило: перед личным окончанием и перед `-л/-ли` после
основы на согласную вставляется `е`: `ид + е + л = идел`, мн. `идели`.

**Обоснование.** Два разных правила для одной фонетической ситуации —
искусственное усложнение. Единое правило «вставка е между согласной основой и
гласным аффиксом» покрывает оба времени и повелительное (`ид + и = иди`
сохраняется: аффикс `и` начинается с гласной, но императив согласных основ —
`+и` без эпентезы по §7.5; см. D-007).

**Следствия.** Реализовано в `verbs.conjugate_past(stem_type=...)`,
`segment_verb` (разбор `идел`), переводчике. Тесты: `test_past_epenthetic_e_*`.

## D-007. Повелительное наклонение — только регулярные формы (2026-11-15, §7.5)

**Контекст.** Пример `писати → пиши` требовал незаявленного чередования
`писа- → пиш-`.

**Решение.** Исключены все чередования в повелительном: гласная основа `+ й`
(`читай`, `писай`), согласная основа `+ и` (`иди`). Формы типа `пиши` в язык
не входят.

**Обоснование.** Прямое следствие принципа «нет исключений». Цена — небольшое
отступление от русской нормы (`писай` вместо `пиши`), приемлемая для
искусственного языка. Общий вопрос чередований (`люб- ~ любл-` и т.п.) в §7
снят жёстко: чередования фиксируются словарём как алломорфы (см. D-011) либо
не используются.

**Следствия.** `verbs.imperative` и `segment_verb` работают без алломорфов;
категория «алломорфы основы» зарезервирована для лексикона, не для грамматики.

## D-008. Двойная роль буквы `ь` (2026-11-15, §2.4)

**Контекст.** `ь` обозначал и мягкость, и замену `ъ` (`обьект`), где смягчать
не надо.

**Решение.** Два регулярных употребления: (1) мягкость — в конце основы и
перед гласными внутри неё; (2) замена `ъ` — разделительный, не смягчает.

**Обоснование.** Иначе произношение не выводится из написания — нарушение
регулярности на фонетическом уровне. Позиция различима: заменяющий `ь` стоит
там, где в русском был `ъ` (после приставки на согласный перед `е/ё`).

**Следствия.** Нормализатор (`normalize_word`) заменяет `ъ → ь` безусловно;
валидатор правило мягкости не проверяет (фонетика вне объёма MVP).

## D-009. Управление предлогами `у`, `с`, `од` (2026-11-15, §8.6)

**Контекст.** Предлоги были в списке без управления; примеры использовали
разные падежи.

**Решение.** `у` (обладатель/близость) → дательный: `у мне`; `с`
(совместность) → дательный: `с нему`; `од` (агент пассива, источник) →
родительный: `од авторо`. Прежний пример `од известний автор` в образце §11
исправлен на `од известний авторо`.

**Обоснование.** Унификация управления — заявленная цель концепции. Дательный
как «косвенный по умолчанию» сводит к минимуму запоминание; родительный у `од`
мотивирован семантикой отделения/источника. Вопрос осознанно закрыт в пользу
простоты: тонкости русского управления (`с кем?` vs `с чем?`) не воспроизводятся.

**Следствия.** Валидатор пока управление предлогов не проверяет (коды
R002/R003/R013 ждут реализации — TODO). Проверка будет опираться именно на
эту таблицу.

## D-010. Порядок слов: единственное отклонение от SVO (2026-11-15, §8.5)

**Контекст.** Заявлен неизменный порядок, но пример с `ли` (`Читаш ли ти?`)
имеет VSO.

**Решение.** Базовый порядок SVO. Единственное регулярное отклонение —
вопрос с частицей `ли`, где глагол может предшествовать подлежащему.
Других свободных перестановок нет; «выделительные» перестановки русского
не воспроизводятся.

**Обоснование.** Либо запретить VSO с `ли` (потеря естественного вопроса),
либо легализовать один узкий случай. Выбрано второе: одно явное правило лучше
неявного «порядок не меняется, кроме тех случаев, когда меняется».

**Следствия.** Валидатор: порядок слов проверяется только как предупреждение
(R010 — в разработке); VSO с `ли` из проверки исключается.

## D-011. Чередования основ — только словарные алломорфы (2026-11-15, §7.1)

**Контекст.** `ити → ид-`, потенциально `люб- ~ любл-`, `пис- ~ пиш-`.

**Решение.** Чередования не описываются грамматическими правилами. Основа с
чередованием фиксируется в лексиконе как отдельная лексема (`ити`, основа
`ид-`). Категория алломорфов (вариантов одной основы) зарезервирована: пока
не используется, вводится только вместе с закрытым списком.

**Обоснование.** Это модель эсперанто: чередования есть в лексиконе, но не в
грамматике. Грамматика остаётся полностью регулярной; небольшой словарный
слой честно декларирует иррегулярность там, где она неизбежна.

**Следствия.** Лексикон хранит основы явно (README §4.5); планируемое поле
`allomorphs` в SQLite-схеме (README §4.6) зарезервировано под будущее.

## D-012. Связка `есть` — инвариантная; пищевой глагол не введён (2026-11-15, §8.3)

**Контекст.** `ест` используется как связка владения (`У мне ест книга`), но
по §7.2 любая согласная основа спрягается (`есем, есеш...`), и возникает
омонимия с «кушать».

**Решение.** `ест` — инвариантная служебная форма-связка (помечена
`invariant` в лексиконе; валидатор не проверяет согласование для неё).
Глагол «есть/кушать» в версию 1.0 не вводится.

**Обоснование.** Спряжение связки не несёт нагрузки (субъект уже выражен
обладателем в дательном), а инвариантность экономит правило-исключение
целого класса. Откладывание пищевого глагола снимает омонимию без решений.

**Следствия.** Переводчик русского «ест/суть» в связке → `ест`. Введение
пищевого глагола (например, `ед-` → `едем, едеш`) — решение версии 1.1
с записью в этот журнал.
